# 05-blocked-or-needs-diff.md - BLOCKED-группы beellama.cpp: чем заблокировано, объём, зависимости

Дочерний документ реестра [beellama.cpp](README.md). Все счётчики и объёмы - как в [07-raw-inventory.md](07-raw-inventory.md), цифра в цифру. Числовые эффекты автора, измеренные на чужих подсистемах, здесь приводятся только как цитаты автора и не переносимы на наш сетап (f16 KV, qwen4exp, CUDA sm_86).

Фундаментальное ограничение всего реестра: форк **не поддерживает qwen4exp** - `qwen4exp` / `LLM_ARCH_QWEN4EXP` / `build_attn_qsa` в дереве форка не найдены (проверено по 07-raw-inventory.md). Модельные оптимизации форка физически не могут нас касаться напрямую.

## BLOCKED: TurboQuant / TCQ prefill MMA (1010625c5, 375555536)

- Ссылка: `1010625c5` "perf: enable turbo4 prefill MMA - pp4096 588->1113 tok/s (1.9x)"; `375555536` "perf: turbo prefill dequant+MMA - 1.78x speedup (98.8% of q8_0)"
- Область: ggml/src/ggml-cuda/, путь квантованного KV TurboQuant/TCQ
- Потенциал: только цифры автора - 1.9x и 1.78x на pp4096. Измерены на TurboQuant-кэше KV. У нас KV в f16 (`-ctk f16 -ctv f16`), типа TurboQuant в нашем дереве нет.
- Чем заблокировано: нет подсистемы - самого квант-типа, метаданных, путей декодирования. В форке тип удержан отдельным preserve-коммитом `1a285c4d1` (см. ниже).
- Сложность: высокая (портирование подсистемы целиком)
- Риск: высокий (меняет layout KV для всех бэкендов)
- Вердикт: не портировать. Цифры автора неприменимы к нашему f16 KV.

## BLOCKED: KVarN - собственный FA-бэкенд с low-bit KV (группа N/A-KVARN-LOWBIT, 3)

- Область: ggml/src/ggml-cuda/fattn-kvarn-dispatch.cu и спутники
- Потенциал: для нашего сетапа нулевой
- Чем заблокировано: KVarN - это отдельный FA-бэкенд форка со своим представлением low-bit KV. У нас `-DGGML_CUDA_FA=ON` (стандартный FA) и KV f16; диспетчера KVarN в нашей базе нет и не предвидится.
- Сложность: высокая, смысла нет
- Риск: n/a
- Вердикт: не портировать (см. 04-not-applicable.md, N/A-KVARN-LOWBIT).

## BLOCKED: семейство спекулятивного декодирования DFlash / SD-* (~100+ коммитов)

- Ссылки: именованные в реестре 6 (`f1a9b5a19` DFlash 22 файла; `5ecbe1ac1` "support DFlash2" 20 файлов; остальные - в 07 по префиксам subject: `dflash` 72 шт., `SD-*` и др.)
- Область: common/speculative*, src/ + серверный обход
- Потенциал: у нас spec decoding выключен (ни DFlash, ни MTP не используем) - ноль
- Чем заблокировано: это не набор независимых оптимизаций, а развиваемая фича форка; точечные коммиты внутри неё не извлекаются без черновика-верификатора.
- Сложность: не применимо
- Риск: n/a
- Вердикт: не портировать (N/A-SPEC-DECODING).

## BLOCKED: preserve-мегамассы (1a285c4d1, 80bb3c794, 686e63aa3)

- Ссылки: `1a285c4d1` "ggml: preserve TurboQuant and TCQ backends" - 163 файла (ggml-cuda 134, metal 9, прочее 8); `80bb3c794` "preserve spec decoding" - 56 файлов; `686e63aa3` "restore local changes" - 118 файлов
- Потенциал: ноль для нас
- Чем заблокировано: это merge-preserving коммиты - форк возвращает свой код при подтягивании upstream. Оптимизаций в них нет, есть удержание чужой кодовой базы. Разбирать построчно бессмысленно.
- Вердикт: не портировать, в реестре не учитывать как оптимизации.

## BLOCKED: бюджеты prompt-cache на сервере форка (c8da45a37, 13ad92aaa)

- Ссылки: `c8da45a37` "Fix prompt-cache host budget enforcement" - 5 файлов (tools/server 3); `13ad92aaa` "server: stop deriving checkpoint budget from cache-ram" - 4 файла
- Область: tools/server (server-context, budget-логика) + common
- Потенциал: теоретически пересекается с нашим `--cache-ram 3000` и `--ctx-checkpoints 3`, но семантика бюджетов в форке отделилась от upstream (форк считает бюджет через свою KVarN/server-машинерию).
- Чем заблокировано: нужен ручной diff серверной budget-логики форка против нашей базы; на 24 наших порта и qwen4exp-путь это не ложится без переделки. В 01-registry отнесено в "Потенциальные, требует ручного разбора".
- Сложность: средняя-высокая (ручной разбор semantics)
- Риск: средний (можно рассинхронизировать checkpoint- eviction с нашим стеком)
- Вердикт: не брать без отдельной задачи; пока чиним эквивалентное поведение портами из CachyLLama (CL-f658fc5af, CL-024dff234 - см. [SUMMARY](../SUMMARY.md)).

## NO-DIFF: ac792986d - fused GDN 4D state fast path

- Ссылка: `ac792986d` "ggml: preserve fused GDN 4D state fast path" - 10 файлов
- Почему NO-DIFF: наша база уже на 3D snapshot API для recurrent state; путь с 4D-состоянием у нас не instantiated. Портить API под этот коммит - значит ломать совместимость ради чужого внутреннего ускорения (детали: 02-applicable.md, раздел "Не применять").

- Ссылка: `91357ddcc` (topk 32->64)
- Почему NO-DIFF: наш сэмплинг идёт с top_k = 20 (конфиг запуска). Ограничение 32 в форке решало проблему верификатора DFlash / Gemma4, у нас её нет. Отклонённый кандидат - строка 12 главной таблицы [SUMMARY](../SUMMARY.md).
